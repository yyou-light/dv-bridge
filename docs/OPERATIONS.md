# 运维与限制

## 在线与状态

有仿真运行时每 300 秒合并查询原任务状态，空闲不查询 Worker。ETX 本地空闲队列轮询约 2 秒，忙时心跳约 8 秒；30 秒内的心跳用于在线判断。这些本地文件操作不占 Windows 剪贴板。

端点可后台常驻，一小时是配对租约而非进程寿命。正常任务结束不调用 `close`。保持图形 ETX 和 Worker 终端可用；端点在线不等于有独立的永久 AI 轮询进程。

## 剪贴板

同一 Windows 会话里的请求经统一入口排队，最多等待 600 秒。锁释放后队列继续，同类请求的近期正常耗时用于调整本地检查间隔，范围为 0.5～2 秒。排队用本地锁与状态文件，无需通过剪贴板探测忙闲。一个请求是否已经发送，以对应的回执为准。

检测到新复制时，普通截图和文字都进入共享的 30 秒保护。每次再复制都重新计时，累计等待预算为 300 秒。静默期满后沿原请求继续。支持 Windows 常见位图格式，位图快照最多 64 MiB，临时保存在本地助手进程内。文字与其他可恢复格式的原有大小保护仍适用。

发送前核对剪贴板变化序号。收发结束时只在仍持有本次内容的情况下恢复原内容。如果现有格式无法备份，发送前返回错误并保留原内容。通信超时后沿原号查回执或续传。每个请求在等待回包时只写一次，同一通信包只回一次，旧回包会触发退让。

## 任务与恢复

一条 Worker 同时一个任务，最多五个不同编号。批量委托不是一个原子事务：每项独立校验、占用与回执。已完成提交由私有进度及回执摘要恢复；不确定项不自动重派，查询原请求。未开始项可以续接，不封锁其他编号。

源码上传必须带基线 SHA256，安装保留事务备份与原子校验。冲突时只处理冲突文件，不重装整套通道。不要为解除占用直接删除锁、任务、私有进度或 FSDB 读取记录。

## 跨节点与 FSDB

接收端和 Worker 可选择不同节点，前提是准确安装根、队列和锁目录一致且可访问。锁使用 POSIX 文件锁；站点的 NFS 跨节点锁语义须先做自己的验收。来源环境的五路成功不等于每种 NFS 的竞争与断连行为都通过。

每个 FSDB 独立保护，正在写入或覆盖的文件不能读取。查询核对结束标记和写入记录，读后检查文件身份未变化。已完成的其他文件及无关 Worker 可继续使用。

波形任务也占用一个匹配的空闲 Worker；有 `workNN` 输出后缀时绑定对应编号。没有匹配闲置编号会报告忙，不应为此取消其他任务或清除占用。不需要另开常驻 Verdi 窗口。

## 从 0.2.0 升级到 0.3.0

0.3.0 的 Windows 客户端会校验 Linux 回包与实际发送的请求一致，升级时要配套更新两端。升级复用已有配置、密钥、配对凭据、Worker、任务号和队列。

1. 暂缓发起新请求，等正在进行的收发和安装事务完成。备份将替换的公开文件和发布清单。
2. 用你所在站点获准的方式更新两端的公开文件，连同同版本的 `config/release.json`。Linux 侧此次运行代码的变化在 `etx/session_agent.py`，Windows 侧包含新的排队脚本与客户端。保留 `.private/`、运行状态目录及原 Worker 进程。
3. 通过站点已有的维护方式只重载 ETX 收发接收端。若由 supervisor 看护，可按下节第 3 步核对接收进程身份并让 supervisor 拉起新版本。
4. 接收端 ready 后，用同版 Windows 客户端做一次只读查询或合成文件回读。检查原任务状态及回执，上传中断时使用原事务和已准备的请求。若升级失败，恢复两端同版本的文件和发布清单，再重载接收端。

## 升级文件能力时保留现有 Worker

0.2.0 增加 256 MiB UTF-8 文本、分段校验及日志摘录。代码发布、本机测试与某个现有 ETX 端点已完成升级是不同状态；以该端点的 `hello` 能力和实际分块往返验收为准。旧端点仍可处理原大小范围内的文本上传；超出旧范围会明确要求升级。

Worker 和剪贴板接收端是独立进程。这次 Linux 核心只需更新 `etx/session_protocol.py`、`etx/session_files.py`、`etx/session_service.py`；Windows 更新 `local/windows_read_files.py` 和 `clients/etx_cli.py`。**保持现有 Worker 进程及其启动环境，保留配置文件原始字节、身份、安装根、队列、锁、任务号与回执。** 不替换 `worker-runtime/`、`session_jobs.py`、`session_control.py`，不清队列，也不重新执行首次配置步骤。正在执行及以后领取的固定任务仍依赖这些配置和模块的摘要。

建议的维护顺序：

1. 在隔离目录验证候选版本及发布摘要，记录安装前源文件 SHA256、现有配置摘要和接收端/Worker 的进程身份。暂停新的文件安装与提交，等待正在进行的文件事务结束；已派发的仿真可继续执行。
2. 使用已获准的核心维护安装流程，在原安装根内按基线 SHA 校验、备份及原子替换更新上述三个 Linux 文件，顺序为 protocol、files、service。普通 `upload` 受业务文件白名单保护，不能假定它能自更新通道安装目录；没有维护权限时停在已验证补丁，不扩大白名单或另建通道。 公开包还校验完整发布清单：升级公开包时，须同步该版本其他已变化的公开文件及匹配的 `config/release.json`，不能只换三个模块而保留旧摘要。未变化的 Worker/runtime 文件应核对摘要相同并保留原文件。内部现行旧安装布局按其自身维护验收更新三个模块，不可用公开包整目录覆盖、替换启动器或套用不匹配的发布清单。
3. 保留原有 supervisor。先用 `receiver.json` 的进程身份和 `/proc` 中的实际启动参数核对原接收进程，再只向该接收进程发送 SIGTERM，等待它完成当前请求并退出。不要使用宽泛的进程名匹配或终止 Worker。持久接收进程收到 SIGTERM 返回非零，既有 supervisor 将在同一配置、身份和状态目录中拉起新一代接收进程；这是短暂的收发中断，不是 Worker 重启。没有可核实的活跃 supervisor 时，先处理这一缺项，不盲目终止接收端。
4. 接收端就绪后完成原生路径/符号链接检查和多块 UTF-8 合成往返，核对 `hello.max_text_file_bytes=268435456`、`native_log_enabled=true`、原任务回执仍可读取，且 Worker 进程身份和占用未改变。Windows 使用匹配客户端；沿用原业务请求号，配对租约按原机制续接。没有完成这些检查前，不宣称线上升级成功。

失败时保留原请求、配置、任务与占用，只按本次维护备份恢复这三个核心文件，再按同一方式重载接收端。不要通过重跑 case 验证文件通道，也不要为回退重建 Worker。

## 大文本、日志与磁盘占用

单文件和单批文本总量最多 256 MiB，每批最多十个文件，每块最多 256 KiB；流式校验不将整份文件放入内存。PDF/Office 的原有只读下载上限仍为 16 MiB，二进制上传和 FSDB 文件下载不在此能力内。接收端会话存储上限为 2 GiB，仍有文件数配额；不要以删除事务备份或任务记录绕过配额。

日志优先用 `native-log` 取得首错上下文和最后摘要；完整读取经 `SessionReadFiles` 落盘后，分析结束保留关键证据，再用同操作号的 `cleanup-logs` 清理本任务的完整本地日志。该操作先核对归属、长度和 SHA256，清理后在摘要中留下来源信息和已清理状态。待恢复的失败传输可暂存；其他读取方式留下的正文分块回执也应在处理完成后按精确路径清理。

该清理不删除 ETX 原始日志和接收端的不可变传输快照，也不删除源码基线及安装/恢复凭据。日志摘录不会生成完整日志快照；需要完整下载时，要将本地临时日志和远端传输缓存分别计入各自磁盘占用。

## 故障定位

- `CONFIGURATION_REQUIRED`：先完成一次私有配置；普通重启不要重新安装。
- `USE_AN_EXISTING_GRAPHICAL_ETX_TERMINAL`：在已经登录的图形 ETX 终端启动，普通 SSH 终端的 DISPLAY 可能为空。
- `ENDPOINT_ACTIVE_ON_OTHER_HOST`：保留现有端点，核对实际归属；不对远端 PID 盲目发信号。
- `ETX_QUEUE_WAIT_TIMEOUT`：请求在本机排队超时，尚未发送。继续时使用原请求。
- `CLIPBOARD_USER_BUSY`：用户复制使本次等待预算用尽。已提交的任务按原 ID 查询。
- `CLIPBOARD_NOT_PLAIN_TEXT`、`CLIPBOARD_FORMAT_NOT_RESTORABLE`：可恢复的文本或位图格式不足，收发保留当前内容。此类错误可能出现在应用自定义格式的剪贴板上。
- `CLIPBOARD_USER_PRIORITY_YIELD`：本地剪贴板 I/O 超时，已退让，按原请求核对回执。
- `PEER_REPLY_BINDING_REQUIRED`：接收端回包缺少 0.3.0 的请求摘要。核对 Windows 与 ETX 两端版本。
- `RELEASE_FILE_CHANGED`：当前文件与发布摘要不符，核对来源；不要关闭校验。
- 波形版本/许可错误：先查该请求自己的启动诊断，不更换工具版本或清理共享会话来重试。
